# Tâche 0.6 — Rôles et pages réservées : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Tout l'espace connecté est protégé par défaut.
- `/formateur` et `/admin` ne s'ouvrent qu'aux rôles concernés ; un étudiant est renvoyé vers l'accueil.
- Les menus suivent les mêmes règles.
- Le compte de l'utilisateur devient super-administrateur.

**Architecture:**
- **Règles.** Elles sont écrites une seule fois, dans `web/src/lib/auth/permissions.ts` (fonctions pures). Les menus et la vérification des pages les utilisent.
- **Vérification.** Chaque page réservée appelle `requireSpace()`, qui lit les rôles en base à chaque requête et redirige si besoin. Elle est faite **dans la page**, pas dans une mise en page : le guide Next « Layouts and auth checks » rappelle qu'une mise en page n'est pas réexécutée à chaque navigation.
- **Proxy.** Il continue de vérifier seulement la connexion, mais à l'envers d'aujourd'hui : il ouvre une liste de pages publiques et protège tout le reste.

**Tech Stack:** Next.js 16 (App Router, `cacheComponents`, proxy), React 19, Supabase (table `roles` de la migration 0001), Vitest 5.

**Spec:** `docs/superpowers/specs/2026-10-10-lot-0-fondations-design.md` (§4 ligne « `/formateur`, `/admin` », §6 « Rôles » et « Ton compte », §7 « Pages protégées », §8 ligne 0.6). Feuille de route : `docs/superpowers/specs/2026-10-09-feuille-de-route-design.md`, ligne 0.6.

## Global Constraints

- **Rôles.** `etudiant`, `formateur`, `moderateur`, `admin`, `super_admin` (spec §6). Un compte peut en avoir plusieurs ; tout compte a `etudiant`.
- **Pages réservées.**
  - `/formateur` et `/admin` sont réservées aux rôles concernés.
  - Un étudiant qui les ouvre est renvoyé vers l'accueil (spec §4).
  - Elles restent « Bientôt disponible » jusqu'aux lots 4 et 6.
- **Attribution des rôles.** Seul un `super_admin` attribue ou retire un rôle : c'est déjà imposé par la base (migration 0001). Le premier `super_admin` est créé par l'utilisateur dans l'éditeur SQL.
- **Mode démonstration.** Il reste tel quel : l'utilisatrice de démonstration a les rôles `etudiant`, `formateur` et `admin`, et voit donc les deux espaces.
- **Habitudes.** Accessibilité, tests d'abord, et commits terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **Adresse tapée à la main.** Un étudiant qui tape `/admin` ou `/formateur` arrive sur l'accueil : il ne voit ni le contenu, ni une erreur. → Task 2.
- **Future page.** Une page de l'espace connecté qui ne figure dans aucune liste (par exemple `/nouvelle-page`) est protégée d'office. → Task 1.
- **Pages publiques.** Les pages publiques restent ouvertes sans compte :
  - connexion, inscription, code, mot de passe oublié, nouveau mot de passe ;
  - conditions, confidentialité, `/etat` ;
  - retours de Google et des e-mails (`/auth/...`).
  → Task 1.
- **Chaque rôle voit ses espaces.**
  - Un modérateur voit le Back-office.
  - Un formateur ne le voit pas.
  - Un super-administrateur voit les deux espaces.
  → Task 2.
- **Espace coché.** Dans le menu du profil, l'espace coché est celui où l'on se trouve (sur `/admin`, c'est « Back-office », plus « Espace étudiant »). → Task 2.

### Task 1: Espace connecté protégé par défaut

**Files:**
- Modify: `web/src/lib/auth/routing.ts`
- Test: `web/tests/auth/session.test.ts`

**Interfaces:**
- Produces:
  - `PAGES_PUBLIQUES = ["/connexion", "/inscription", "/verification-email", "/mot-de-passe-oublie", "/nouveau-mot-de-passe", "/conditions", "/confidentialite", "/etat", "/vitrine", "/auth"]`. Une adresse est publique si elle est égale à l'un de ces chemins ou commence par l'un d'eux suivi de `/`.
  - `routeFor` garde sa signature. La racine `/` est traitée comme aujourd'hui. Une adresse non publique sans connexion mène à `/connexion?next=…`, ou à `?session=expiree` s'il y avait une session. `ECRANS_DE_COMPTE` est inchangé : un compte connecté qui les ouvre va à l'accueil.

- Ruling à reporter au journal : sans compte, une adresse inconnue (`/nimporte-quoi`) mène à la connexion plutôt qu'à la page introuvable. C'est le prix d'une protection par défaut. Une fois connecté, la page introuvable s'affiche comme avant. Le site public du lot 1 ajoutera ses pages à `PAGES_PUBLIQUES`.

### Task 2: Règles d'accès, pages réservées et menus

**Files:**
- Create: `web/src/lib/auth/permissions.ts`, `web/src/lib/auth/require-space.ts`, `web/src/components/layout/ReservedComingSoon.tsx`
- Modify: `web/src/app/(app)/formateur/page.tsx`, `web/src/app/(app)/admin/page.tsx`, `web/src/components/ui/ProfileMenu.tsx`, `web/src/components/layout/MobileProfileMenu.tsx`, `web/src/components/layout/HeaderActions.tsx`
- Test: `web/tests/auth/permissions.test.tsx`

**Interfaces:**
- Consumes: `getShellUser(): Promise<ShellUser | null>`, `type Role` (de `ProfileMenu`), `ComingSoon`, `comingSoonMetadata`.
- Produces:
  - `permissions.ts` (pur, sans import serveur) :
    - `type Espace = "etudiant" | "formateur" | "admin"` (déplacé depuis `ProfileMenu`, qui l'importe).
    - `ACCES: Record<Espace, Role[] | "tous">` :
      - `etudiant` : `"tous"` ;
      - `formateur` : `["formateur", "super_admin"]` ;
      - `admin` : `["moderateur", "admin", "super_admin"]`.
    - `canAccess(espace: Espace, roles: Role[]): boolean`.
    - `spaceOf(pathname: string | null): Espace` : `/formateur…` donne `formateur`, `/admin…` donne `admin`, le reste (et `null`) donne `etudiant`.
  - `require-space.ts` (serveur) : `requireSpace(espace: Espace): Promise<ShellUser>`. Sans compte, `redirect("/connexion")`. Sans le rôle, `redirect("/accueil")`. Sinon, il renvoie le compte.
    - **Note pour la 0.5** : sa Task 3 remplacera `/connexion` par `/auth/sortie`, ici comme dans la mise en page.
  - `ReservedComingSoon({ espace, page }: { espace: Exclude<Espace, "etudiant">; page: PageAVenir })` (composant serveur asynchrone) : `await requireSpace(espace)`, puis `<ComingSoon page={page} />`. Il est dans son propre fichier, car une page Next ne peut exporter que `default`, `metadata`, etc.
  - **Pages** `formateur` et `admin` :
    - `metadata` est inchangé ;
    - le corps est `<Suspense fallback={null}><ReservedComingSoon espace="…" page="…" /></Suspense>`.
    - Rien de la page n'est rendu avant la vérification.
  - **Menus** :
    - `ProfileMenu` et `MobileProfileMenu` construisent les espaces avec `canAccess` (fini les listes de rôles recopiées) ;
    - `HeaderActions` passe `currentSpace={spaceOf(usePathname())}` à `ProfileMenu`.
- Ruling à reporter au journal : le super-administrateur passe partout, y compris dans l'Espace formateur, pour pouvoir tout vérifier. Le modérateur entre dans le Back-office ; ce qu'il y voit sera réglé au lot 6 (permissions fines).

- [ ] **Step 1: Écrire les tests**
  - `chaque rôle ouvre ses espaces` : tableau de cas pour `canAccess` :
    - `["etudiant"]` : formateur → `false`, admin → `false`, etudiant → `true` ;
    - `["etudiant", "formateur"]` : formateur → `true`, admin → `false` ;
    - `["etudiant", "moderateur"]` : admin → `true` ;
    - `["etudiant", "super_admin"]` : formateur → `true`, admin → `true`.
  - `l'espace se lit dans l'adresse` :
    - `spaceOf("/admin")` et `spaceOf("/admin/utilisateurs")` donnent `admin` ;
    - `spaceOf("/formateur")` donne `formateur` ;
    - `spaceOf("/administration")` et `spaceOf(null)` donnent `etudiant`.
  - `un étudiant qui tape /admin retourne à l'accueil` : avec `getShellUser` simulé (`roles: ["etudiant"]`), `requireSpace("admin")` lève `NEXT_REDIRECT:/accueil`.
  - `sans compte, retour à la connexion` : `getShellUser` → `null` ; `requireSpace("formateur")` lève `NEXT_REDIRECT:/connexion`.
  - `un administrateur ouvre le back-office` : avec les rôles `["etudiant", "admin"]`, `render(await ReservedComingSoon({ espace: "admin", page: "admin" }))` affiche « Back-office » et « Bientôt disponible ».
  - `chacun voit ses espaces dans le menu du téléphone` :
    - un super-administrateur voit « Espace formateur » et « Back-office » ;
    - un formateur ne voit pas « Back-office ».
  - `l'espace où l'on se trouve est coché` : avec `usePathname` simulé à `/admin`, on ouvre le menu du profil ; « Back-office » a `aria-current="page"`, « Espace étudiant » ne l'a pas.
