# Tâche 0.3 — Coque de l'application : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** L'espace connecté a sa coque (en-tête, barre latérale, barre du bas sur téléphone, menus du profil et des notifications, déconnexion), chaque entrée du menu mène à une page (vraie ou « Bientôt disponible »), et une adresse inconnue affiche la page 404 du design.

**Architecture:** Un groupe de routes `web/src/app/(app)/` partage un `layout.tsx` qui pose la coque `AppShell` (`web/src/components/layout/`). Les entrées de menu, leurs icônes et le lot d'arrivée de chaque écran vivent dans une seule source, `web/src/lib/navigation.ts`. Les parties qui dépendent de l'adresse courante (entrée active) ou d'un état (menus, fenêtre de déconnexion) sont des composants client ; le reste est rendu côté serveur. Pas encore de connexion (tâche 0.4) : la coque affiche un utilisateur de démonstration, `DEMO_USER`, que la 0.4 remplacera par le profil connecté.

**Tech Stack:** Next.js 16 (App Router, `cacheComponents`), React 19, Tailwind 4, composants de la tâche 0.2, `radix-ui`, Vitest 5 + Testing Library + jsdom.

**Spec:** `docs/superpowers/specs/2026-10-10-lot-0-fondations-design.md` (§3 organisation du dossier, §4 écrans du lot 0, ligne 0.3 du §8). Feuille de route : `docs/superpowers/specs/2026-10-09-feuille-de-route-design.md` (§4, pour le lot d'arrivée de chaque écran).

**Source des valeurs visuelles :** l'artefact « Étudium — Nouveau design » (https://claude.ai/artifact/9Ei2bCdhG75Nr3KnFZQxfg), fichiers `project/NdAccueil.dc.html` (en-tête et barre latérale), `NdNotificationsOuvertes`, `NdMesFormationsMenu`, `NdDeconnexion`, `NdMobAccueil` (téléphone), `NdMobMenu` (page « Profil » du téléphone), `NdMobDeconnexion` (fenêtre en feuille du bas), `NdMobNotifications`, `Nd404`.

## Global Constraints

- Fidélité : mêmes dimensions, couleurs, arrondis et espacements que les écrans du design. En cas de doute, l'écran fait foi (il prime aussi sur les planches « Composants » quand ils diffèrent).
- Réutiliser les composants de `web/src/components/ui/` ; ne créer un nouveau composant d'interface que si aucun ne convient, et le placer alors dans `ui/`.
- Coque : à partir de 1024 px (`lg`), en-tête complet + barre latérale de 337 px + panneau blanc ; en dessous, en-tête compact (logo, série, cloche) + panneau blanc + barre du bas. Pas de tiroir sur tablette : la mise en page téléphone s'étire (le design n'en montre pas, et la spec du lot 0 ne le demande pas).
- Aucune donnée inventée présentée comme réelle : l'utilisateur de démonstration est un objet `DEMO_USER` unique, nommé comme tel, lu par la coque seulement.
- Textes en français, vouvoiement ; chaque page a un `<title>` « [Page] · Étudium ».
- Accessibilité : lien d'évitement « Aller au contenu » ; entrée active `aria-current="page"` ; tout est utilisable au clavier ; zones de toucher de 44 px (utilitaire `cible-tactile`).
- Pas de défilement horizontal de la page, de 320 px à 1440 px de large.
- Chaque commit se termine par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **Entrée active sur une sous-page** : sur `/mes-formations/quelque-chose`, « Mes formations » reste active ; `/formations-gratuites` n'active pas « Toutes les formations ». → test `isActive` dans Task 1.
- **Lien mort** : chaque entrée de menu (barre latérale, barre du bas, page « Profil » du téléphone, menu du profil, en-tête) mène à une page existante. → test dans Task 4 (chaque lien a son fichier `page.tsx`).
- **Petits écrans et écrans bas** : à 320 px de large, rien ne déborde ; téléphone en paysage (hauteur 360 px), le contenu défile et la barre du bas reste visible. → vérification dans Task 7.
- **Déconnexion au clavier** : depuis le menu du profil, « Se déconnecter » ouvre la confirmation, Échap la ferme et le focus revient au rond de profil. → test dans Task 3.
- **Noms longs** : un prénom ou une adresse e-mail très longs sont coupés avec « … » dans le menu du profil et sur la page « Profil » du téléphone, sans élargir la page. → test dans Task 4.

## Validation de la tâche 0.3 (par l'utilisateur)

`npm --prefix web run dev`, puis http://localhost:3000/accueil : sur ordinateur et sur téléphone, on passe par toutes les entrées du menu, on ouvre les notifications et le menu du profil, on se « déconnecte » (retour à la page de départ), et une adresse inventée affiche la page 404.
